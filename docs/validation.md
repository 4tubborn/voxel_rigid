# 验证记录

验证对象：Voxel Rigid 0.1，Minecraft Java Edition **26.3 正式版**，原版服务端，OpenJDK 25.0.2，纯原版数学后端。

## 已完成验证

- 数据包被正式版服务端加载，函数、宏和 context_float_provider 无加载/解析错误。
- 155 个函数、625 个数值提供器的 JSON 与静态引用检查通过。
- 12 项游戏内数值自测，`/function vr:test/run` 返回 **0**，`#fail vr.test = 0`。
- 检查范围包括轴对齐分离/重叠、0.25 穿透、旋转后分离/重叠、穿过后终点分离的扫掠检测、TOI 二分上界、等质量弹性碰撞、中心接触无旋转、四元数归一化与重力。
- 一个单位方块在 y=60 石头平台上落地；修复绝对整数坐标自动居中后，COM X/Z 与内部坐标一致。落地质心约 y=61.4757，速度归零；约 0.0243 格静态穿透属于当前位置求解器已观察到的限制。
- 两个空中方块初始 vx=+0.2/-0.2 block/tick，显式运行 5 个模拟 tick 后 vx 约为 -0.0196036/+0.0196036；验证了实体对枚举、BVH、SAT 与冲量响应链路。
- 水池中的 density=0.7 方块显式运行 20 模拟 tick 后质心 y≈66.368、vy≈+0.2530；density=2.0 的三体素 bar 下沉至平台附近 y≈61.6506、vy≈-0.01108。证明浮力方向与密度关系正确，不构成水面长期稳定性的验收。
- marker 与 block_display 均被正常生成、按 owner ID 连接；服务端 Display NBT 更新成功。

测试用地形、forceload 和控制命令只用于临时测试世界，安装包不会创建测试平台、强制加载区块或修改 gamerule。

## 重现数值测试

```mcfunction
function vr:api/pause
function vr:test/run
scoreboard players get #fail vr.test
```

无玩家时自测 tellraw 没有收件人，但函数返回值和记分项仍有效。为了让测试可重复，应在空旷空气区域附近执行；本测试包含一次实际环境中的积分调用。

**`/tick freeze` 不可作为数据包逻辑的暂停器。** 本项目测试使用 `vr:api/pause`，再显式调用 `vr:tick/dimension` 驱动确定数量的模拟 tick。

## 验证边界

没有进行客户端视觉验收、多人网络压力测试、跨维度长时间移动、任意半砖/楼梯真实碰撞形状测试，也没有完成成熟引擎级堆叠稳定性、旋转 CCD、能量/角动量守恒测试。

数学库适配文件来自已读取的实际接口，但整套 math3.2 / math3.2_lalib 集成运行未验证；默认包没有依赖它们。

复杂形状的生成器上限为 64 体素，不代表服务端保证能同时实时模拟多个 64 体素刚体。接触列表最多 32 个/批次，多接触丢弃会影响稳定性；命令链预算中途终止也会破坏本 tick 完整性。首先从少量简单形状测试，依据 docs/architecture.md 的计数与分析扩大规模。

## 性能实测

临时测试世界已加载 25 个强制加载区块，两个单位方块在平台/水池场景中运行。原版 `/tick sprint 100` 报告 **43 tick/s，23.23 ms/tick**；当次接触溢出计数为 0。该数字包含服务器、区块和引擎开销，仅代表本容器、该场景的一次样本，没有空载对照与重复分布，不可外推到用户机器或复杂堆叠。它也表明当前基线还需要显著优化，不能据此宣称已达到大量复杂刚体实时模拟的目标。
